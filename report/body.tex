\noindent\textbf{Abstract---}%
Cloud services run as replicated virtual machines (VMs) spread over a network of servers. Where those replicas sit decides how long every user request waits. We model the infrastructure as a weighted graph whose nodes are sites and whose edge weights are link latencies, and we place service replicas to minimise demand-weighted mean latency subject to CPU, memory and budget constraints. The problem contains the $p$-median problem and is NP-hard, so we combine exact polynomial algorithms where they apply with greedy heuristics where they do not: minimum spanning trees (Prim, Kruskal) for the provisioning backbone, single- and all-pairs shortest paths (Dijkstra, Bellman-Ford, Floyd--Warshall, Johnson) for routing and the latency matrix, 0/1 and multiple-choice knapsack dynamic programs for budgeted selection, four greedy schedulers refined by local search, and a mixed-integer program that certifies optimality on small instances. We evaluate on ten networks, including the real Abilene and NSFNET backbones, 25 Indian and 24 Nigerian cities at real coordinates, and the Woxsen University campus. Greedy placement with local search lands within 0.5\,\% of the proven optimum on average (worst case about 3\,\%) at roughly a fifth of the exact solver's time. Under tight capacity, packing-first placement remains feasible where latency-first greedies fail. All results are reproducible through a tested Python package, a REST API and an interactive web dashboard.

\noindent\textbf{Keywords---} replica placement, $p$-median, shortest paths, minimum spanning tree, knapsack, submodularity, local search, mixed-integer programming.

\section{Introduction}
A request to an online service travels from the user's nearest network site to a server that holds a copy (\emph{replica}) of the service. Its delay is dominated by propagation along fibre (about 5\,$\mu$s per km) and per-hop switching. Placing replicas close to demand therefore reduces latency, but servers have finite CPU and memory, replicas cost money, and a server chosen for one service may be needed by another. Deciding where to run what is a combinatorial optimisation problem on a graph.

This project builds \emph{Lightpath}, a complete placement system, and uses it to study three questions:
\begin{enumerate}[label=\textbf{Q\arabic*},leftmargin=*]
  \item Which classical graph algorithms are appropriate at each stage, and how do their theoretical bounds compare with measured behaviour in Python?
  \item How close do fast greedy schedulers get to the true optimum, and what does closing the gap cost?
  \item How do network size, density, capacity pressure and budget change the answer?
\end{enumerate}
\textbf{Contributions.} (i) A clean formulation of capacitated, budgeted, multi-service replica placement and a 7-stage pipeline that solves it (Section~\ref{sec:model},~\ref{sec:algo}). (ii) Implementations of every algorithm from first principles, including binary, Fibonacci and pairing heaps and union-find, with correctness arguments and complexity bounds. (iii) A transfer-cost model in which some links have negative cost but negative cycles provably cannot occur, which motivates Bellman-Ford and Johnson. (iv) Eight experiments with an exact MILP reference. (v) Policy outputs (routes, schedules, cost/benefit tables) and an interactive dashboard for India, Nigeria and the Woxsen campus.

\section{Problem Formulation}\label{sec:model}
\textbf{Network.} $G=(V,E)$ is an undirected graph of $n=|V|$ sites and $m=|E|$ links. Link $(u,v)$ has latency $\ell_{uv}$ (ms) and bandwidth $b_{uv}$ (Gbit/s). For geographic networks we use
\begin{equation}\label{eq:lat}
\ell_{uv} = 1.3\cdot\frac{d_{\text{km}}(u,v)}{200\ \text{km/ms}} + 0.3\ \text{ms},
\end{equation}
where 200\,km/ms is the speed of light in fibre, 1.3 accounts for cable detours, and 0.3\,ms models switching. $d(u,v)$ denotes the shortest-path latency between sites.

\textbf{Servers and services.} A subset $S\subseteq V$ are servers with CPU capacity $C_s$, memory $M_s$ and activation cost $f_s$; routers have $C_s=0$. Each service $j\in J$ needs $c_j$ vCPU and $\mu_j$ GB per replica, costs $p_j$ per replica-hour, has priority $\pi_j$, demand $r_{jc}$ (requests/s) at client sites $c$, and between $k^{\min}_j$ and $k^{\max}_j$ replicas.

\textbf{Decision and objective.} Binary $y_{sj}=1$ if a replica of $j$ runs on $s$ (at most one per server, for fault isolation). Each client is served by its nearest replica, so with weights $w_{jc}=\pi_j r_{jc}$ we minimise
\begin{equation}\label{eq:obj}
L(y)=\frac{\sum_{j}\sum_{c} w_{jc}\,\min_{s:\,y_{sj}=1} d(c,s)}{\sum_{j}\sum_{c} w_{jc}}
\end{equation}
subject to $\sum_s y_{sj}=k_j$, $k^{\min}_j\le k_j\le k^{\max}_j$, $\sum_j c_j y_{sj}\le C_s$, $\sum_j \mu_j y_{sj}\le M_s$ for every server, and the hourly budget $\sum_j p_j k_j \le B$. An optional server budget $\sum_{s \text{ active}} f_s\le B_S$ switches servers off.

\textbf{Hardness.} With one service, unlimited capacity and fixed $k$, the problem is exactly the $p$-median problem, which is NP-hard on general graphs \cite{kariv1979}. Capacities add bin-packing structure, which is NP-hard by itself. This justifies exact algorithms for the polynomial sub-problems (paths, trees, pseudo-polynomial knapsacks) and heuristics with a measured optimality gap for placement.

\textbf{Transfer costs with negative edges.} Replicas of the same service synchronise data. Moving data $u\to v$ costs
\begin{equation}\label{eq:cost}
\kappa(u\!\to\!v)=\beta+\gamma\,\ell_{uv}+\varphi(u)-\varphi(v)\quad(\$/\text{GB}),
\end{equation}
where $\varphi$ is a regional price level (lower at core data centres, with a deterministic per-site jitter). Arcs into higher-priced regions become negative: a rebate.
\begin{lemma}\label{lem:nocycle}
The directed graph with weights~\eqref{eq:cost} has negative arcs but no negative cycle.
\end{lemma}
\begin{proofsketch}
Around any directed cycle the terms $\varphi(u)-\varphi(v)$ telescope to zero, so the cycle's cost is $\sum(\beta+\gamma\ell_{uv})>0$.
\end{proofsketch}
\noindent Lemma~\ref{lem:nocycle} is the same potential argument that underlies Johnson's reweighting. It guarantees that Bellman-Ford and Johnson always succeed, while Dijkstra is unsafe because of the negative arcs. In the India network 24 of 88 directed arcs are negative.

\subsection{Data structures}
The graph is stored as adjacency lists (one hash map per vertex), giving $\Theta(n+m)$ space and $O(\deg u)$ neighbour scans. Four addressable priority queues share one interface (\textit{push}, \textit{pop}, \textit{decrease-key}): a binary heap with a position map ($O(\log n)$ for all operations), a Fibonacci heap with cascading cuts (amortised $O(1)$ insert and decrease-key, $O(\log n)$ extract-min \cite{fredman1987}), a two-pass pairing heap, and Python's \texttt{heapq} with lazy deletion. Kruskal uses union-find with union by rank and path compression, $O(\alpha(n))$ amortised per operation \cite{tarjan1975}.

\subsection{Minimum spanning tree (backbone)}
The MST is the cheapest set of links that keeps every site connected, which is the first set of links to provision. Prim grows one tree from a root and repeatedly adds the lightest edge leaving it \cite{prim1957}. Kruskal scans edges in increasing weight and keeps those that join two components \cite{kruskal1956}.
\textit{Correctness} for both follows from the \emph{cut property}: for any cut $(X,V\setminus X)$ a lightest crossing edge belongs to some MST. Prim's choice is such an edge for the cut (tree, rest), and Kruskal's for the cut separating either endpoint's component. Disconnected inputs yield a spanning forest.
\textit{Complexity:} Prim $O((n+m)\log n)$ with a binary heap and $O(m+n\log n)$ with a Fibonacci heap; Kruskal $O(m\log m)$ for sorting plus $O(m\,\alpha(n))$. The pipeline selects Prim when $m>n\log_2 n$ and Kruskal otherwise.

\subsection{Single-source shortest paths}
\begin{algorithm}[!htbp]
\caption{Dijkstra with an addressable heap}\label{alg:dij}
\small
\begin{algorithmic}[1]
\Require graph $G$, non-negative weights $w$, source $s$
\State $\mathit{dist}[v]\gets\infty$ for all $v$; \ $\mathit{dist}[s]\gets 0$; \ $Q\gets\{s\}$
\While{$Q\neq\emptyset$}
  \State $u\gets$ \Call{ExtractMin}{$Q$} \Comment{$u$ is settled: $\mathit{dist}[u]=\delta(s,u)$}
  \For{each edge $(u,v)$ with $v$ not settled}
    \If{$\mathit{dist}[u]+w(u,v)<\mathit{dist}[v]$}
      \State $\mathit{dist}[v]\gets \mathit{dist}[u]+w(u,v)$; \ $\mathit{parent}[v]\gets u$; \ \Call{PushOrDecrease}{$Q,v$}
    \EndIf
  \EndFor
\EndWhile
\end{algorithmic}
\end{algorithm}
\textbf{Dijkstra} (Algorithm~\ref{alg:dij}) \cite{dijkstra1959}. \textit{Invariant:} when $u$ is extracted, $\mathit{dist}[u]$ equals the true distance $\delta(s,u)$. Suppose $u$ is the first vertex extracted with $\mathit{dist}[u]>\delta(s,u)$. On a shortest $s\leadsto u$ path, let $y$ be the first unsettled vertex and $x$ its settled predecessor. Then $\mathit{dist}[y]=\delta(s,y)\le\delta(s,u)<\mathit{dist}[u]$ because weights are non-negative, so $y$ would have been extracted first, a contradiction. Time: $O((n+m)\log n)$ with a binary heap, $O(m+n\log n)$ with a Fibonacci heap. Our implementation rejects negative weights explicitly.

\textbf{Bellman-Ford} \cite{bellman1958,ford1956} relaxes every arc in rounds. By induction, after round $i$ every vertex whose shortest path uses at most $i$ arcs has its correct distance; simple paths have at most $n-1$ arcs, so $n-1$ rounds suffice, and any improvement in round $n$ certifies a reachable negative cycle (which we extract by walking parent pointers). Time $O(nm)$, with early exit when a round changes nothing. It computes cheapest replica-synchronisation routes under~\eqref{eq:cost}.

\subsection{All-pairs shortest paths}
\textbf{Floyd--Warshall} \cite{floyd1962,warshall1962} is dynamic programming over intermediate vertices: with $d_k(i,j)$ the shortest $i\leadsto j$ distance using intermediates in $\{1..k\}$,
$d_{k}(i,j)=\min\{d_{k-1}(i,j),\ d_{k-1}(i,k)+d_{k-1}(k,j)\}$, because a shortest path either avoids $k$ or passes through it once (no negative cycles). $\Theta(n^3)$ time, $\Theta(n^2)$ space, and a negative diagonal entry exposes a negative cycle. We provide a pure-Python version and a NumPy version that vectorises the $(i,j)$ loop; both are still $\Theta(n^3)$.
\textbf{Johnson} \cite{johnson1977} adds a vertex $q$ with zero-cost arcs to all vertices, computes potentials $h=$ Bellman-Ford$(q)$, and reweights $w'(u,v)=w(u,v)+h(u)-h(v)\ge 0$ (triangle inequality). Every $s\leadsto t$ path changes by the constant $h(s)-h(t)$, so shortest paths are preserved and Dijkstra can run from every vertex: $O(nm+n(n+m)\log n)$.
\textbf{Choice rule.} Counting both directions of each undirected link, the pipeline treats a graph as sparse when $m\log_2 n<n^2$. Sparse graphs use repeated Dijkstra (or Johnson if any weight is negative); dense graphs use vectorised Floyd--Warshall. Section~\ref{sec:exp} tests this rule.

\subsection{Knapsack dynamic programs (budgeted selection)}
\textbf{0/1 knapsack (server activation).} Each server has value $b_s$, the capacity-scaled latency saving it offers relative to an average server, and weight $f_s$. With costs scaled to integer cents ($W$ = budget in cents),
$\mathrm{OPT}[i][w]=\max\{\mathrm{OPT}[i-1][w],\ \mathrm{OPT}[i-1][w-f_i]+b_i\}$. \textit{Correctness:} by exchange, an optimal set for items $1..i$ either excludes item $i$ (optimal for $1..i-1$ at the same budget) or includes it (item $i$ plus an optimal set at budget $w-f_i$). Time and space $\Theta(nW)$, which is pseudo-polynomial; one bit per cell is kept for reconstruction. Because $b_s$ is an additive surrogate, a repair step re-adds high capacity-per-dollar servers if the minimum replicas would not fit.

\textbf{Multiple-choice knapsack (replica sizing).} For each service the options are $k\in[k^{\min}_j,k^{\max}_j]$ with cost $kp_j$ and value equal to the weighted-latency saving over $k^{\min}_j$, estimated by an uncapacitated greedy placement. Exactly one option per group gives $\mathrm{OPT}[g][w]=\max_{o\in g}\mathrm{OPT}[g-1][w-w_o]+v_o$ in $\Theta(W\sum_g|g|)$. Since this estimate ignores bin packing, a \emph{capacity repair} then removes the largest extra replicas until a first-fit-decreasing (FFD) packing exists. That guarantees at least one feasible placement downstream.

\subsection{Greedy schedulers and local search}
Let $F_j(T)=\sum_c w_{jc}\,(P-\min_{s\in T}d(c,s))$ be the latency \emph{saving} of placing service $j$ on server set $T$ (with $P$ a large constant). $F_j$ is monotone and submodular: adding a server helps less when more servers are already open.
\begin{itemize}[leftmargin=*]
\item \textbf{Demand-first:} services in decreasing demand; each replica goes to the server nearest the next demand hotspot that still has room.
\item \textbf{Marginal gain (CELF):} a global heap of (service, server) pairs keyed by marginal saving; stale keys are re-evaluated lazily, which is valid because submodularity means gains never increase \cite{leskovec2007}. Without capacities, greedy maximisation of a monotone submodular function under a cardinality constraint achieves at least $(1-1/e)$ of the optimal saving \cite{nemhauser1978}.
\item \textbf{Regret:} repeatedly place the service whose best and second-best feasible servers differ most, the classic generalised-assignment heuristic \cite{martello1990}. It protects services with few good options from being crowded out.
\item \textbf{FFD packing:} replicas sorted by CPU descending, each placed on a fitting server chosen by latency saving among the tightest-fitting half. If that gets stuck it falls back to plain FFD, which uses at most $\tfrac{11}{9}\mathrm{OPT}+\tfrac{6}{9}$ bins for one-dimensional packing \cite{dosa2007}.
\end{itemize}
\textbf{Local search} repeatedly applies the best improving \emph{relocate} (move one replica to a free server) or \emph{swap} (exchange replicas of two services between two servers when both fit). Candidate relocations are evaluated in a vectorised way using each client's nearest and second-nearest replica. Every accepted move strictly lowers~\eqref{eq:obj} and the number of placements is finite, so the search terminates in a local optimum. For uncapacitated $k$-median, single-swap local optima are within a factor 5 of optimal \cite{arya2004}.

\subsection{Exact MILP and batch scheduling}
For the optimality reference we solve
$\min \sum w_{jc}d(c,s)x_{csj}/\sum w_{jc}$ s.t.\ $\sum_s x_{csj}=1$, $x_{csj}\le y_{sj}$, $\sum_s y_{sj}=k_j$, and the capacity rows, with $y$ binary and $x\in[0,1]$, using HiGHS \cite{huangfu2018} through SciPy \cite{virtanen2020}. The disaggregated constraints $x\le y$ give a tight LP relaxation, which we also report as a lower bound when the MILP is too large. Services that no server can host keep the same penalty in both the MILP and the heuristics, so the objectives match. For background \emph{batch jobs}, a list scheduler orders jobs longest-first (LPT) and assigns each to the server lane with the earliest finish time after its input data arrives (latency plus size over bottleneck bandwidth). Without transfer delays, LPT is within $\tfrac43-\tfrac1{3m}$ of the optimal makespan \cite{graham1969}.

\section{Implementation and Verification}\label{sec:impl}
Lightpath is a Python package (\texttt{cloudplace}) with modules for core data structures, algorithms, the problem model, data generators and the end-to-end solver. A FastAPI service exposes datasets, network generation, solving and step-by-step algorithm traces. A React/TypeScript dashboard (Fig.~\ref{fig:ui}) offers a placement studio with live solving, an algorithm lab that replays traces alongside pseudocode, experiment charts, dataset downloads (JSON, Gephi GEXF, CSV) and a guided tour. When the Python service is not running, the dashboard falls back to saved results so it also works on a static host.

\textbf{Testing.} 191 automated tests check every algorithm against independent references. MST weights, single-source distances (including negative arcs) and all-pairs matrices from every heap and algorithm are compared with NetworkX \cite{hagberg2008} on random graphs. 0/1 and multiple-choice knapsack results are compared with brute force. The MILP is compared with exhaustive search on small placements, and it lower-bounds every heuristic. Further tests check heap operations with property-based testing, verify that greedy placements never exceed capacity, check that batch-schedule lanes never overlap, confirm that the transfer-cost graph never contains a negative cycle on any dataset (Lemma~\ref{lem:nocycle}), and check that the web server cannot be tricked into serving files outside its directory. \section{Experiments and Results}\label{sec:exp}
All timings are medians of repeated runs in CPython~3.13 on a single core. Quality experiments average three seeds. The full suite runs in about 80 seconds and writes CSV files and the figures below.

\textbf{E1, priority queues (Fig.~\ref{fig:e1}).} The Fibonacci heap has the best asymptotic bound but is consistently slower: at $n=1000$ Dijkstra takes 25.9\,ms with it against 17.7\,ms with the binary heap, and at $n=4000$ 196\,ms against 144\,ms. Its pointer-based nodes and consolidation cost more in an interpreter than the saved $O(\log n)$ decrease-keys. \texttt{heapq} with lazy deletion (implemented in C) is fastest up to $n=2000$ but falls behind at $n=4000$ (212\,ms) as stale entries accumulate on dense graphs. Bellman-Ford on the transfer graph costs 490\,ms at $n=4000$, reflecting its $O(nm)$ bound.

\textbf{E2, all pairs (Fig.~\ref{fig:e2}).} On dense graphs the choice is clear-cut: at $n=400$ vectorised Floyd--Warshall needs 277\,ms against 5015\,ms for Johnson and 5323\,ms for repeated Dijkstra, and the rule correctly selects it. \textbf{E5, capacity pressure (Fig.~\ref{fig:e5}).} At nominal capacity every method is feasible. FFD packing stays feasible at every capacity level, and local search then brings its latency within a few percent of optimal. Under tight capacity, feasibility and latency pull in different directions, and packing first is the safer strategy.

\textbf{E6, density (Fig.~\ref{fig:e6}).} On Erd\H{o}s--R\'enyi graphs with $n=80$, raising the edge probability from 0.025 to 0.7 cuts the optimal mean latency from 7.71\,ms to 2.59\,ms, with diminishing returns beyond $p\approx0.2$. \textbf{E7, budget frontier.} On the India network, raising the VM budget lets the multiple-choice knapsack buy replicas where they help most. \section{Recommendations}\label{sec:rec}
\begin{enumerate}[leftmargin=*]
\item \textbf{Default solver:} run all four greedy schedulers with local search and keep the best. This lands within 0.5\,\% of optimal on average at a fraction of the exact cost. Run the MILP as a certificate whenever it has fewer than about 60k variables.
\item \textbf{Capacity first when load is high:} when minimum-replica load exceeds about 30\,\%, start from FFD packing, then refine for latency (E5).
\item \textbf{Spend by marginal value:} size replicas with the multiple-choice knapsack and buy the next replica with the best ms-per-dollar ratio from the cost/benefit table. Returns diminish quickly (E7).
\item \textbf{Provision the MST backbone first, but route on the full graph:} routing over the tree alone would stretch latency by 1.2--1.6$\times$.
\item \textbf{Engineering in Python:} prefer binary heaps or \texttt{heapq} over Fibonacci heaps (E1), and choose all-pairs algorithms with constants measured on the actual implementation (E2).
\item \textbf{Transfer pricing:} with negative costs, use Bellman-Ford or Johnson only. The potential form~\eqref{eq:cost} keeps rebates safe from negative cycles.
\end{enumerate}

\section{Limitations and Future Work}
India and Nigeria use real city locations but synthetic links, and Woxsen's fibre plan and server sizes are modelling assumptions. Demand is static, and latency ignores queueing and congestion. The activation stage uses an additive surrogate value, so it is not optimal for the joint problem. Timings reflect CPython constants. Natural extensions are online re-placement as demand shifts, queueing-aware latency (for example M/M/$c$ servers), multi-objective cost--latency fronts, carrier topology data such as the Internet Topology Zoo \cite{knight2011}, and a compiled core for larger instances.

\section{Conclusion}
Lightpath shows how classical algorithm design fits a practical systems problem. Exact algorithms (MST, Dijkstra, Bellman-Ford, Floyd--Warshall, Johnson) and pseudo-polynomial dynamic programs handle the tractable parts. Greedy schedulers with local search handle the NP-hard placement. An exact MILP shows the heuristics are within 0.5\,\% of optimal on average, while the experiments expose where asymptotic theory and practical constants disagree. The same pipeline produces deployable policies for national networks in India and Nigeria and for the Woxsen campus.
