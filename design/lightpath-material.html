How to use Lightpath

Lightpath decides where to run copies of online services on a network of servers, so that users get answers as fast as possible without overloading any server or going over budget. You do not need to know the algorithms to use it.

Start here

Four steps get you from nothing to a full placement plan.

  1. Pick a regionChoose India or Nigeria with the switch at the top of Home. Everything on the site follows that choice.
  2. Open the studioPress "Open the placement studio", or Studio in the left rail.
  3. Set it up and solveChoose a network, set a budget, and press "Solve placement".
  4. Read the planThe map shows where each service runs, the right panel shows how good the plan is, and the tabs give the details.

What each page does

Landing

The first screen. It names the project and the people behind it.

How to use it
  • Press "Enter Lightpath" or the Enter key to go to the site.

Home

A one-page overview of the project, with a live map of the selected region.

How to use it
  • Switch between India and Nigeria at the top.
  • Each moving dot on the map is a user request travelling the fastest path to the nearest copy of its service.
  • The four tiles summarise the best plan found.
  • Click any network card at the bottom to open it in the studio.

Placement studio

Where you run the planner and explore its answer.

How to use it
  • Set the controls on the left, then press "Solve placement".
  • Explore the plan on the map and in the tabs underneath.
  • Read the score and advice on the right.

How to use it
  • Pick an algorithm and a starting city.
  • Press play, or step forward and back, and follow the highlighted line of pseudocode.

Using the studio

The studio has three parts: controls on the left, the map with its tabs in the middle, and the results on the right. Every panel has a small "?" button that explains it on the spot.

Controls
Network
Which network to plan for: India, Nigeria, the Woxsen campus, or one of the test networks.
VM budget
Dollars per hour you can spend on copies of services. More budget buys more copies, which brings services closer to users, but each extra copy helps less than the one before.
Server budget
Optional. Limits which servers are switched on, picking the most useful ones that fit the budget.
Replica sizing
How many copies each service gets. "Knapsack DP" finds the best mix for your budget; "Minimum" and "Maximum" are for comparison.
Strategies
The placement methods to compare. "Local search refinement" improves each method's answer. "Exact MILP check" computes the true best answer on small networks so you can see how close the fast methods get.
Solve placement
Runs everything and refreshes the map, tabs and results.
Map
Backbone (MST)
Shows, in red, the cheapest set of links that still connects every site.
Replicas
Yellow sites host copies of services; the small coloured dots around them say which services.
Routes
The path each group of users takes to reach its nearest copy.
Service chips
Click a service to show only its copies and routes. "All services" shows everything.
Moving around
Scroll to zoom, drag to move, and hover any site to see its load and what runs there.
Tabs under the map
Routes
Who is served from where, along which path, and how fast. Click a row to highlight that route on the map.
Servers
How full each server is. Red bars are nearly full; these are the places where extra capacity would help most.
Cost and benefit
Average delay for each number of copies of each service, with the option the budget bought marked in blue, and what the next copy would save.
Replica sync
How copies of the same service keep each other up to date: the fastest path versus the cheapest path, which can use links that pay a rebate.
Batch jobs
A timeline of background jobs on each server. The red dashed line marks when the last one finishes.

Reading the results

Average latency
How long a typical request waits for the network, in milliseconds. Lower is better.
95th percentile
95 out of 100 requests are at least this fast. It shows how the slowest users fare.
VM cost
What the plan costs per hour.
Full pipeline
How long the computer took to produce the whole plan.
Strategy chart
One bar per method; shorter is better. The dashed green line is the proven best answer, so a bar touching it is optimal.
Recommendations
The plan explained in plain sentences, including where one more dollar or one more server would help most.

Words used on the site

LatencyThe delay before data arrives, in milliseconds (ms). 1 ms is a thousandth of a second.
Node and linkA node is a site such as a city, data centre or campus building. A link is the cable between two sites.
ReplicaA copy of a service running on a server. More copies in more places means shorter trips for users.
CapacityHow much processing power (CPU) and memory a server has. Copies cannot exceed it.
Shortest pathThe fastest route between two sites through the network (Dijkstra, Bellman-Ford, Floyd–Warshall, Johnson).
Spanning tree (MST)The cheapest set of links that keeps every site connected (Prim, Kruskal).
Knapsack DPA method that picks the best combination of options that fits within a budget.
Greedy methodA fast method that makes the best-looking choice at each step.
Local searchTakes a plan and keeps making small swaps while they improve it.
Exact optimum (MILP)The provably best plan. Slow on big networks, so it is used as a reference on small ones.
GapHow far a method's plan is from the proven best, in percent. 0% means optimal.
Rebate linkA link that pays you to send data over it (a negative cost), which is why some routes use special algorithms.
